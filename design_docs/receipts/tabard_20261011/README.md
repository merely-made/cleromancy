# Cleromancy shared appearance acceptance

**Accepted 2026-10-11.** The native consultation now uses Tabard's registry,
choice persistence, appearance resolution and shared workshop, with Cambium's
title-bar slots and native host bindings. Tinct owns canonical mode derivation.
The host owns which saved appearance is applied; existing consultation workers,
storage and graph authority retain their present behavior.

Missing preferences preserve the original dark consultation colors and write
nothing. Four canonical modes keep Cleromancy's built-in identity and seeds.
The editable dark copy supplies portable preview roles and scoped original
product colors. Authored CSS remains exact and last in the product cascade.
The editor uses the shared neutral workshop cascade and foreground. Its C
monogram replaces a star unsupported by this host's current font.

Save updates a definition. Apply publishes the saved presentation. Saving under
an applied identity holds the installed snapshot until explicit Apply, including
Save → Back → Edit. Failed writes and corrupt files preserve prior bytes and
presentation. An unreadable library disables authoring until safe reload.
Exports protect the consultation root and overridden preference destinations.
The native wrapper does not dispatch reading or reflection commands from
appearance actions.

## Remaining boundaries

This acceptance covers appearance in the existing native consultation, not C1.
The divination plan retains resident/domain/view/store migration ownership. Mode
selection, persistence and paints are qualified here; a complete product WCAG
contrast review is not claimed.
Optional personal-sync, admission and analytic feature runtime behavior is
unqualified; its legacy raw tag reader remains outside this change. Windows,
Linux, real reset recovery, unrelated app surfaces and arbitrary authored CSS
are not qualified by these finite macOS fixtures. The extra live preview run qualifies unsaved CSS Apply and Discard/Back in the
native workshop. Other dirty-close outcomes, export and failed-write ownership
have mounted CPU regressions and are not claimed as separate headed scenarios.
